# P1-03 — Read-only target probe и restore plan

**Статус:** READY (P1-01 принята 2026-09-23). **Поток:** планирование.
**Владелец:** `restore/probe.py`, `restore/plan.py`, `tests/unit/test_restore_plan.py`.

- `restore plan` проверяет доверенный backup через существующий verifier,
  именованную цель, SSH identity, ОС/архитектуру, зависимости, место, конфликты
  путей/контейнеров/volumes и доступные безопасные факты registry.
- Отсутствующий Docker/Certbot описывается как план установки; source probe,
  требующий уже работающий стек, не использовать для чистой цели без адаптации.
- Привязать plan к target/source identity, backup/manifest/tool digest, роли,
  сроку действия и исходным фактам. Разные alias одной машины не разрешают restore.
- Показать изменяемые ресурсы, операции установки, место для передачи/распаковки,
  конфликтующие данные и отдельную границу активации. Unknown — блокировка
  либо явно отложенная проверка до записи данных, но не подтверждённая готовность.
- **Решение P1-01 (2026-09-23):** source record получать только read-only чтением
  `request.json` исходной задачи через закреплённый host key source; иначе — полные
  пины манифеста. Матрица ОС: только Ubuntu 24.04 x86_64.
- **Готово:** plan не пишет на VPS, не устанавливает и не делает pull; тесты
  same-source target, смены host key, пустой цели, stale plan, недостатка места,
  повреждённого backup и неизвестной ОС проходят.
