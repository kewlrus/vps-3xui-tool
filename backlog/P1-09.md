# P1-09 — Guarded activate и защита от двух активных OAuth-копий

**Статус:** READY (P1-01 принята 2026-09-23). **Поток:** активация приложений.
**Владелец:** `restore/activate.py`, `tests/unit/test_restore_activate.py`.

- Принимать только согласованную staged-job, проверенные IDs/mounts/digests и
  актуальные доказательства cutover по P1-01. Повторять gate под lock перед start.
- Source должен быть фактически остановлен и защищён от повторного старта на
  время передачи роли. Сетевой timeout, DNS, один флаг или исторический source
  report этого не доказывают; независимый канал управления также нужен.
- Запускать только включённые утверждённые ресурсы в нужном порядке; не делать
  автоматический cutover, source shutdown, генерацию/refresh или старт telemt.
- При частичной активации фиксировать реальные target-эффекты и безопасный
  дальнейший шаг. Не запускать source автоматически: после refresh на target
  старый `auth.json` может быть неактуален. Откат требует сначала остановки target.
- **Решение P1-01 (2026-09-23):** fencing допустим маскировкой docker.service/socket
  или `restart_policy: no` у всех контейнеров; TTL доказательств cutover 300 с.
- **Готово:** тесты source-running/unknown, stale evidence, отсутствующего
  fencing, нового container ID, повторного activate и частичного start проходят;
  ни один отрицательный gate не запускает вторую LiteLLM.
