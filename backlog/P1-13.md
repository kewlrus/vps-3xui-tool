# P1-13 — Публичный CLI, SSH/release и интеграция с P0

**Статус:** WAIT P1-03, P1-04, P1-09, P1-10, P1-11, P1-12.
**Поток:** общая интеграция.
**Владелец:** `cli.py`, `errors.py`, `hostops.py`, `adapters/ssh.py`, `remote_ops.py`,
`release.py`, необходимые `bin/` entrypoints, общие изменения metadata/verifier,
`tests/unit/test_restore_cli.py` и `tests/integration/test_restore_launch.py`.

- Подключить реальные handlers всех шести команд: restore plan/prepare/stage/
  activate/verify и certbot activate. Поддержать один объект `--json`, безопасные
  ошибки, нужные `--apply`, выбор manifest/source evidence и ID по P1-01.
- Расширить fixed SSH protocol и закреплённый release без generic remote exec;
  target должен исполнять проверенную версию со всеми необходимыми модулями.
- Подключить job status для restore и согласованное продолжение стадий; source
  `job recover` не должен случайно интерпретировать target-job как backup.
- Если P1-01 потребовал metadata evolution, реализовать согласованную версию
  здесь с явной совместимостью. Сохранить чтение корректных P0-копий; недостаток
  source evidence сообщать явно, не объявлять такую копию безопасной для activate.
- **Итог P1-01:** metadata evolution не потребовалась (backup format 1 без изменений);
  source record — read-only чтение `request.json` исходной задачи на source.
- **Готово:** CLI end-to-end через synthetic transport, потеря ответа после
  регистрации, запуск shipped entrypoints и P0 regressions проходят. В командах
  нет заглушек, неиспользуемых handlers и зависимости от клиента после принятия job.
